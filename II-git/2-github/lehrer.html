2.9 GitHub (kurz)

Dauer: ca. 5 Min. (optional)

Worum geht's

GitHub ist ein Online-Dienst, auf dem man Git-Repositories sichern und teilen kann. Git funktioniert komplett ohne GitHub; GitHub ist nur die Wolke dazu. Nur Erklärung und höchstens eine kurze Demo. Wenn die Zeit knapp ist, weglassen.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • Git (lokal) und GitHub (online) auseinanderhalten.
  • sagen, wozu man GitHub braucht (Backup, Teilen, Zusammenarbeit).
  • wissen, dass ein Repository privat oder öffentlich sein kann.

So erklären wir es

  1. Das Bild: Skihütte und Gipfelbuch. Dein lokales Repository ist dein Notizbuch im Rucksack. GitHub ist das Gipfelbuch oben: Hier liegt eine Kopie, andere können sie lesen oder mitschreiben, und wenn dein Rucksack verloren geht, ist sie noch da.
  2. Drei Gründe für GitHub:
    • Backup: Die Festplatte stirbt, das Projekt lebt.
    • Teilen: Link schicken, fertig.
    • Zusammenarbeit: mehrere Menschen am selben Projekt.
  3. Zwei Begriffe, mehr nicht:
    • Push: eigene Commits hochladen.
    • Clone: ein Repository von GitHub auf den eigenen Rechner holen.
  4. Privat oder öffentlich. Standard sollte privat sein. Öffentlich sieht es die ganze Welt, auch alles im Verlauf (2.7).

    Was auf GitHub öffentlich liegt, liegt für immer im Netz. Darum: erst .gitignore, im Zweifel privat.

  5. Konto nötig. Kostenlos, aber nicht heute zwingend. Der Workshop läuft komplett ohne. Datenschutz: O.1. Dort geht es auch darum, dass Dateien dann bei einem Dienstleister liegen.

    Für die Kursleitung: Kurs-Repo freigeben. Das Repo hinter dieser Webseite (github.com/tillg/makers-toolkit, GitHub-Logo unten in der Fußzeile) ist privat. Wer einen Account angelegt hat, nennt uns den Username. Wir laden ihn als Mitarbeiter:in ein: Settings → Collaborators → Add people, oder im Terminal gh api -X PUT repos/tillg/makers-toolkit/collaborators/<username>. GitHub schickt eine Einladung per Mail, die Teilnehmenden nehmen sie an. Erst dann sehen sie das Repo. Achtung: Eingeladene dürfen auch pushen (Stand 2026-11).

  6. Ausblick: Wer das später will, bittet Claude: „Hilf mir, dieses Projekt auf GitHub zu sichern.“ Das taucht in 6.4 Die nächste Stufe wieder auf.

Zeigen (Live-Demo)

Optional, 2 Minuten, mit unserem eigenen Konto: Ein fertiges Repository (Segeltörn-Planer) auf github.com im Browser zeigen: Dateiliste, Commit-Verlauf mit Nachrichten, ein Diff. Das Bild „Dieselbe Zeitleiste, nur online“ reicht. Wir pushen nicht live (Anmeldung kostet zu viel Zeit und ist für Teilnehmende nicht nachvollziehbar). Wer fragt, bekommt es nachher gezeigt.

Selbst machen (Übung)

Keine Übung. Reflexionsfrage:

Würdest du dein Projekt privat oder öffentlich stellen? Was dürfte auf keinen Fall mit hoch?

Stolpersteine & Fragen

  • „Brauche ich ein Konto?“ Heute nicht.
  • Anmeldung beim Hochladen: Die Anmeldung läuft heute über den Browser oder das Werkzeug gh, nicht mit dem Passwort im Terminal. Vor dem Workshop prüfen, falls wir es doch zeigen.
  • „Ist das sicher?“ Privat: nur eingeladene Personen. Trotzdem nie Passwörter hochladen (O.3).
  • Uni-/Schul-Material: Regeln der Einrichtung beachten, nicht alles darf ins Netz.
  • Dropbox statt GitHub? Für Projekte nicht gleichwertig, siehe O.4.
