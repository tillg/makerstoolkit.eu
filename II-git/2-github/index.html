GitHub

Teil II · Git · ca. 5 Min. · Braucht: Git

GitHub ist ein Online-Dienst, auf dem man Git-Repositories teilen und sichern kann. Optional – Git funktioniert komplett offline auf deinem Rechner.

Remote und origin

Dein Repository liegt auf deinem Rechner. Eine Kopie davon kann zusätzlich im Internet liegen, z. B. auf GitHub. Diese zweite Kopie heißt Remote (entfernt).

  • Ein Repository kann mehrere Remotes haben. Meist ist es genau eins.
  • Das Standard-Remote heißt origin. Das ist nur ein Spitzname für die Adresse, z. B. https://github.com/dein-name/dein-projekt.
  • Beide Kopien sind vollständig, mit dem ganzen Verlauf. Sie gleichen sich aber nicht von selbst ab. Das machst du mit drei Befehlen.

fetch, pull, push

flowchart LR
  local["Dein Rechner<br/>(lokales Repository)"]
  remote["GitHub<br/>(origin)"]
  local -- "push: hochladen" --> remote
  remote -- "fetch: nur nachsehen" --> local
  remote -- "pull: holen und einbauen" --> local
Befehl Was passiert Bild
git push Deine neuen Commits gehen zu GitHub. Brief abschicken
git fetch Git schaut nach, was es auf GitHub Neues gibt, ändert aber deine Dateien nicht. In den Briefkasten schauen
git pull Neues von GitHub holen und in deinen Stand einbauen (fetch + merge). Brief holen und einsortieren
  • Erst committen, dann pushen. Nur Commits wandern zu GitHub, keine ungespeicherten Änderungen.
  • Arbeitest du an zwei Rechnern oder mit anderen: vor dem Weiterarbeiten pullen.
  • Haben zwei Leute dieselbe Stelle geändert, gibt es beim Pull einen Merge-Konflikt. Den löst du wie jeden anderen.

Claude fragen: „Verbinde dieses Repository mit einem neuen privaten GitHub-Repository und pushe es.“ · „Gibt es auf GitHub etwas Neues, das ich noch nicht habe?“

Vor dem ersten Push: .gitignore

Die Datei .gitignore ist eine Liste. Was darin steht, beobachtet Git nicht. Es landet also nie in einem Commit und nie auf GitHub. Wie eine Packliste „bleibt zu Hause“: Den Rucksack nimmst du mit, den Kühlschrank nicht.

Was gehört hinein?

  • Vertrauliches: Passwörter, Zugangsschlüssel, z. B. die Datei .env.
  • Großes: Videos, riesige PDFs, Datensätze.
  • Erzeugtes: Dinge, die ein Programm jederzeit neu macht, z. B. die Ordner tmp/ oder node_modules/.

So sieht sie aus, eine Zeile pro Eintrag:

.env
tmp/
*.mp4

*.mp4 heißt: alle Dateien, die auf .mp4 enden.

Achtung: Was einmal committet ist, bleibt im Verlauf, auch wenn du die Datei später löschst. Ist ein Passwort einmal auf GitHub, gilt es als verraten. Dann sofort ändern. Darum: .gitignore vor dem ersten Commit anlegen.

  • Die .gitignore selbst committest du mit.
  • Sie beginnt mit einem Punkt und ist darum im Mac-Finder unsichtbar (einblenden mit Cmd+Shift+.). VS Code zeigt sie.

Claude fragen: „Leg eine .gitignore an, die .env, den Ordner tmp/ und alle Videos ausschließt.“ · „Steht in meinem Projekt etwas, das nicht auf GitHub gehört?“

Wir legen uns einen GitHub-Account an

Stand 2026-11. Kostenlos, ein privates Repository kostet nichts.

  1. Registrieren: https://github.com/signup. E-Mail-Adresse und ein starkes Passwort eingeben, am besten aus dem Passwort-Manager.
  2. Username wählen: Er ist öffentlich und steht in jeder Adresse, z. B. github.com/anna-maier. Lieber schlicht und dauerhaft als witzig.
  3. E-Mail bestätigen: GitHub schickt einen Code.
  4. Plan: Free reicht völlig.
  5. Zwei-Faktor-Anmeldung (2FA) einrichten: Settings → Password and authentication. Zum Beispiel mit einer Authenticator-App auf dem Handy. GitHub verlangt das ohnehin bald. Die Wiederherstellungs-Codes gut aufheben.
  6. Mit deinem Rechner verbinden: Am einfachsten über VS Code. In der Quellcodeverwaltung auf Publish Branch bzw. Publish to GitHub klicken. Der Browser öffnet sich, du meldest dich an und bestätigst. Danach dürfen Git und Claude für dich pushen.

Schüler:in oder Student:in? Mit dem GitHub Student Developer Pack bekommst du Extras gratis. Das ist optional.

Geschafft, wenn du auf github.com eingeloggt bist und dein erstes Repository dort siehst.
