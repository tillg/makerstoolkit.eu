1.3 Das Terminal

Dauer: ca. 10 Min.

Worum geht's

Das Terminal ist ein Textfenster, in dem man dem Computer Befehle schreibt, statt zu klicken. Claude Code lebt dort, und wir tippen fast nur ein Wort: claude. Alles andere formuliert Claude.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • ein Terminal öffnen und in einem Projektordner claude starten,
  • mit Strg+C bzw. Esc etwas abbrechen und mit /exit Claude beenden,
  • (optional) Tabs und geteilte Fenster nutzen.

So erklären wir es

  1. Alltags-Bild: Das Terminal ist wie Messenger mit dem Computer. Genauer: Das Terminal ist das Telefon-Handset, die Shell ist die Person am anderen Ende, die dich versteht und ausführt, was du sagst ([KB] 23, §The words people mix up).

    Statt Dateien anzuklicken, schreibst du dem Computer eine Zeile, er antwortet mit Text. Das ist alt, aber sehr direkt. Und genau das kann ein Agent gut: Er kann Befehle schreiben und Ergebnisse lesen.

  2. Warum dort? Im Terminal kann Claude Programme starten, Dateien anlegen und Ergebnisse prüfen, ohne dass wir etwas kopieren müssen. Bild: Der Agent sitzt in der Werkstatt, das Terminal ist sein Arbeitsplatz.
  3. „Keine Angst“: Wir lernen vier Dinge, nicht mehr:
    • Wo bin ich? Das Terminal arbeitet in einem Ordner (steht im Prompt).
    • claude starten.
    • Esc stoppt Claude mitten in der Arbeit, das Bisherige bleibt. Strg+C bricht ebenfalls eine laufende Arbeit ab. Wartet Claude auf deine Eingabe: erstes Strg+C löscht die getippte Zeile, zweites Strg+C beendet Claude (Stand 2026-11, [KB] 25, §Control while it works).
    • /exit beendet Claude auch.
    • Vorsicht: Esc zweimal schnell bei leerem Eingabefeld öffnet das Rückspul-Menü (/rewind, siehe 2.6). Kein Schaden, aber verwirrend. Steht schon Text im Feld, löscht Esc Esc ihn stattdessen.
  4. Terminal-Wahl:
    • Mac/Linux: Ghostty, schnell und modern, optional.
    • Windows: Windows Terminal (bei Windows 11 dabei).
    • Immer möglich: Terminal in VS Code (Terminal → Neues Terminal). Das nutzen wir in 1.4, weil Dateien und Terminal in einem Fenster sind.
  5. Tabs und Splits (nur Ghostty): Neuer Tab Cmd + T, Fenster teilen Cmd + D (so im Handout, auf macOS; unter Linux andere Tasten, vor dem Workshop prüfen). Nutzen: links Claude, rechts ein zweites Terminal, oder zwei Claude-Sessions nebeneinander (Ausblick auf 5.5).

Zeigen (Live-Demo)

  1. Terminal öffnen, zeigen: leeres Fenster, ein Cursor, Ordnername im Prompt.
  2. claude tippen, einmal „Hallo, wo bin ich?“ fragen. Claude nennt den Ordner.
  3. Während Claude arbeitet Esc drücken: es stoppt.
  4. /exit.
  5. (Ghostty) Cmd + T und Cmd + D vorführen.

Zwei harmlose Befehle zum Mitmachen, um das Gefühl zu bekommen:

pwd      # Mac/Linux: zeigt den aktuellen Ordner
ls       # Mac/Linux: listet Dateien (Windows PowerShell: dir)

Selbst machen (Übung)

Alle öffnen ein Terminal, starten claude, fragen „In welchem Ordner bin ich und was liegt hier?“ und beenden mit /exit. Geklappt: Claude nennt einen Ordnernamen. Reflexion: „Was war anders als im Chat?“ (Claude sieht den Ordner.)

Stolpersteine & Fragen

  • Windows: PowerShell oder CMD? Egal, claude läuft in beiden. Prompt PS C:\ = PowerShell.
  • Unser Handout nennt Cmd: Gilt nur Mac. Windows Terminal hat andere Kürzel. Wir zeigen die Splits nur bei Ghostty.
  • „Ich habe etwas kaputt getippt!“ Kaum möglich bei claude, pwd, ls. Fremde Befehle aus dem Internet nicht blind einfügen. Wir fragen im Zweifel Claude, was ein Befehl tut.
  • Fenster reagiert nicht: Esc, dann Strg+C (nicht zweimal schnell hintereinander im Leerlauf, das beendet Claude). Zur Not Tab schließen.
  • Warum nicht die Desktop-App oder der Browser? Geht auch (Doku nennt eine Desktop-App). Der Workshop zeigt das Terminal, weil es überall gleich aussieht und die Grundlage für alles Weitere ist.
  • Falscher Ordner: Claude arbeitet im Ordner, in dem man es startet. Mit cd wechseln oder (einfacher) Ordner in VS Code öffnen, dort Terminal öffnen.
