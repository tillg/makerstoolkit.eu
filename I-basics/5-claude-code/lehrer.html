1.1 Was ist agentische KI?

Dauer: ca. 10 Min.

Worum geht's

Ein Chatbot antwortet, ein Agent erledigt. Ein Agent bekommt eine Aufgabe, arbeitet sie in mehreren Schritten selbst ab und prüft sein Ergebnis. Dahinter steckt trotzdem ein Sprachmodell: ein belesener Autor, keine Datenbank.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • den Unterschied zwischen Chatbot und Agent in eigenen Worten erklären,
  • sagen, warum ein Agent Dateien lesen und schreiben darf (und was das bedeutet),
  • einschätzen, dass KI-Antworten plausibel klingen, aber geprüft werden müssen.

So erklären wir es

  1. Einstieg über die Demo. Die Live-Demo (Doppelpendel, siehe ablauf.md) läuft schon vor diesem Thema. Wir knüpfen daran an:

    Eben habe ich keine Zeile Code geschrieben. Ich habe gesagt, was ich will. Der Agent hat Dateien angelegt, das Programm gestartet und geschaut, ob es läuft. Das ist der Unterschied zu dem, was ihr aus dem Chat kennt.

  2. Chatbot vs. Agent, mit Bild. Reise-Beispiel:

    Chatbot: Du fragst eine Freundin, die schon mal in Kroatien war: „Welche Marinas gibt es?“ Sie antwortet. Den Plan baust du selbst. Agent: Du gibst einer Assistentin den Auftrag „Plane mir einen Segeltörn“. Sie liest die Hafenhandbücher, rechnet Distanzen, legt eine Tabelle an und sagt dir, was noch fehlt.

    An die Tafel/Folie: Tabelle aus dem Handout (Du fragst / Du gibst eine Aufgabe; Kopieren & Einfügen / liest und schreibt Dateien; ein Schritt / viele Schritte).

  3. Drei Modi, ein Bild [CW] S. 12: mit einer klugen Kollegin reden (Chat), an einen Assistenten delegieren (Cowork), eine Werkstatt betreten (Code). Wir sind heute in der Werkstatt. Claude Code ist das Werkzeug dafür.

  4. Was steckt drin: belesener Autor, keine Datenbank [CW] S. 4, 8:

    Ein Sprachmodell sagt das nächste plausible Wort voraus. Es schlägt nichts nach. Stell dir einen unglaublich belesenen Autor vor, der in jedem Stil schreiben kann, aber neu schreibt, statt Fakten nachzuschlagen.

    Drei Fakten dazu, kurz (Stand 2026-11, [KB] 26, §Three facts that explain most behaviour):

    • Es sagt Wort für Wort das nächste voraus. Beispiel „Der Wind dreht auf …“: „Südwest“ ist wahrscheinlich, „Nord“ auch, „Marmelade“ fast nie. Gezogen wird eines davon, deshalb kann dieselbe Frage zwei Antworten geben. (Beispiel ausgedacht, keine echten Zahlen.)
    • Sein Wissen endet an einem Stichtag (bei den aktuellen Claude-Modellen Juni 2026). Es lernt nicht aus unserem Gespräch.
    • Es hat kein Gedächtnis: Claude Code schickt bei jeder Anfrage das ganze Gespräch noch einmal mit. Was nicht im Gespräch steht, weiß es nicht.

    Folge: Ideen, Entwürfe, Zusammenfassungen sind seine Stärke. Exakte Zahlen, Daten, Quellen muss man prüfen. Gleiche Frage zweimal kann zwei Antworten geben. Das ist Absicht (gut zum Brainstormen, riskant bei Zahlen).

  5. Der Agent hat Hände. Er hat Werkzeuge: Dateien lesen, schreiben, Programme starten, im Web suchen. Deshalb fragt er im Manual-Modus vor wichtigen Aktionen (siehe 1.7 Berechtigungen). Seit Claude Code v2.1.283 startet er im Auto-Modus: Dann entscheidet ein zweites Modell, was harmlos ist, und man bekommt nur eine Meldung, wenn etwas blockiert wird. Wir schalten in 1.4 auf Manual, um die Abfragen zu lernen. Die Arbeitsweise dahinter ist immer eine Schleife: Kontext sammeln (lesen, suchen) → handeln (ändern, ausführen) → prüfen → wiederholen, bis es passt ([KB] 1, §The agent loop).

  6. Rollen: Wir formulieren, planen, prüfen. Der Agent tippt. Kein Programmierkurs.

Zeigen (Live-Demo)

Kurz (3 Min.), nicht die große Einstiegs-Demo wiederholen. Gleiche Frage zweimal:

Chat (claude.ai im Browser): Plane mir einen Segeltörn in Kroatien, 7 Tage, 4 Personen.

Dann im Terminal mit Claude Code, im leeren Ordner:

Lege eine Datei toern-plan.md an mit einem Tagesplan für einen Segeltörn in Kroatien, 7 Tage, 4 Personen. Mach eine Tabelle mit Tag, Strecke und Hafen.

Hinweisen: Der Chat liefert Text zum Kopieren. Der Agent legt die Datei an, wir sehen sie im Ordner. Beim zweiten Mal Zahlen (Distanzen) als „zu prüfen“ markieren.

Selbst machen (Übung)

Reflexionsfrage in 2er-Gruppen (2 Min.): „Welche Aufgabe aus deinem Alltag würdest du an einen Agenten geben, welche nie? Warum?“ Einige Antworten einsammeln. Typische Ergebnisse: Recherche, Ordnen, Entwürfe: ja. Entscheidungen, Fakten ungeprüft übernehmen: nein.

Stolpersteine & Fragen

  • „Ist das nicht einfach ChatGPT?“ Gleiche Technik (Sprachmodell), anderer Rahmen: Der Agent hat Werkzeuge und arbeitet in Schleifen.
  • „Denkt die KI?“ Wir bleiben nüchtern: Sie erzeugt plausible Texte und handelt damit. Ob man das Denken nennt, ist offen. Wichtig ist: prüfen.
  • „Darf der Agent alles auf meinem Rechner?“ Nein, er arbeitet im Projektordner. Im Manual-Modus fragt er vorher, im Auto-Modus prüft ein zweites Modell. Details in 1.7.
  • Datenschutz-Fragen: Gelesene Dateien gehen an den Anbieter. Verweis auf die optionale Einheit O.1 (Datenschutz).
  • „Wird die KI mich ersetzen?“ Ehrlich: offene Frage. Heute: Wer sie gut führt, schafft mehr.

1.4 Die erste Agenten-Session

Dauer: ca. 15 Min.

Worum geht's

Erster echter Kontakt: Ordner anlegen, in VS Code öffnen, claude starten, Dateien anlegen und ändern lassen. Der Agent arbeitet im Projektordner, und wir sehen jede Datei sofort links in VS Code entstehen.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • einen Ordner in VS Code öffnen und dort Claude Code starten,
  • Claude Fragen zum Ordner stellen und Dateien anlegen lassen,
  • eine Datei per Anweisung ändern lassen und das Ergebnis in VS Code sehen.

So erklären wir es

  1. Der Projektordner ist die Werkstatt.

    Claude sieht nur den Ordner, in dem du es startest. Alles, was drin liegt, kann es lesen. Was draußen liegt, nicht. Deshalb: ein Ordner pro Projekt.

  2. Vier Schritte (wie im Handout): Ordner anlegen (mein-projekt) → in VS Code öffnen (Datei → Ordner öffnen) → Terminal in VS Code (Terminal → Neues Terminal) → claude.
  3. Drei Prompts, die steigern: erst fragen (liest nur), dann anlegen (schreibt), dann ändern (liest und schreibt). Das zeigt den Weg vom Chatbot zum Agenten.
  4. Beim ersten Start fragt Claude, ob es diesem Ordner vertrauen soll. Wir erklären: Das ist die erste Sicherheitsstufe, mehr in 1.7.
  5. Auf Manual umschalten. Seit Claude Code v2.1.283 startet eine Session im Auto-Modus: Ein zweites Modell gibt harmlose Aktionen selbst frei, man bekommt nur eine Meldung, wenn etwas blockiert wird. Wir wollen aber die Abfragen sehen und lesen lernen. Darum einmal Shift+Tab drücken (Windows: ggf. Alt+M). In der Fußzeile steht dann manual mode on statt auto mode on. Den Auto-Modus erklären wir in 1.7 als „für später“. Das Lesen von Dateien und eingebaute Nur-Lese-Befehle (ls, cat, git status) fragen auch im Manual-Modus nie. ([KB] 25, §Permission modes)
  6. Wie man spricht: normale Sätze, kein Spezialwort. Je genauer das Ziel, desto besser. Beispiele aus mehreren Domänen zeigen, was „genau“ heißt:
    • Physik: „Lege pendel.md an: Erkläre in 5 Sätzen, warum ein Doppelpendel chaotisch ist.“
    • Berge: „Lege tour.md an mit drei Tagestouren im Karwendel, je mit Aufstieg und Gehzeit.“
    • Wirtschaft: „Lege budget.md an: Tabelle Einnahmen/Ausgaben für eine WG.“
  7. Der ELI5-Trick: Versteht man eine Rückfrage oder Antwort von Claude nicht, einfach ELI5 tippen (Explain Like I'm 5, „Erklär es mir, als wäre ich fünf“). Claude erklärt dann ohne Fachwörter. Früh zeigen, damit sich niemand scheut nachzufragen. Nicht-Verstehen ist kein Fehler, sondern ein Prompt.

Zeigen (Live-Demo)

Mit dem Segeltörn-Beispiel (beispielprojekte.md), im leeren Ordner segeltoern. Erst claude starten, dann einmal Shift+Tab, Fußzeile zeigen (manual mode on):

Was befindet sich in diesem Ordner?

Lege eine Datei ideen.md an mit drei Ideen für einen Segeltörn im Mittelmeer.

Mach aus der Liste eine Tabelle mit Spalten für Aufwand und Spaßfaktor.

Hinweise beim Zeigen: (1) Claude zeigt, was es tun will, und fragt (Berechtigung, im Manual-Modus). Der erste Prompt fragt nicht, denn Lesen ist immer erlaubt. (2) ideen.md erscheint in der VS-Code-Seitenleiste. (3) Beim dritten Prompt liest Claude die Datei erst, dann ändert es sie. Nicht gleich alles erklären, Neugier wecken.

Selbst machen (Übung)

Alle machen die drei Prompts mit ihrem eigenen Thema (Material oder Beispiel-Thema). Geschafft, wenn ideen.md mit einer Tabelle im Ordner liegt. Wer fertig ist: „Füge eine Spalte ‚Was ich vorher klären muss‘ hinzu.“ Wir gehen herum und helfen bei Terminal-Problemen.

Stolpersteine & Fragen

  • Terminal öffnet im falschen Ordner: Ordner in VS Code öffnen, dann Terminal. Unten im Terminal steht der Ordnername.
  • Claude fragt etwas, das ich nicht verstehe: ELI5 tippen (siehe oben). Erst antworten, wenn die Frage klar ist.
  • Claude fragt gar nicht: Die Session läuft im Auto-Modus (Fußzeile auto mode on). Shift+Tab einmal drücken, bis manual mode on dasteht. Bei jedem Neustart von claude startet wieder Auto, dann erneut umschalten.
  • Claude fragt dauernd: Gewollt, siehe 1.7. Nicht „immer erlauben“ klicken, solange man nicht versteht, was gefragt wird.
  • Antwort kommt langsam: Normal. Esc stoppt.
  • Ergebnis weicht ab (Tabelle sieht anders aus): Nicht-deterministisch, das ist normal (1.1). Nachfragen, nicht neu anfangen.
  • Datei nicht sichtbar in VS Code: Seitenleiste neu laden oder prüfen, ob derselbe Ordner offen ist.
  • „Kann Claude auch meine PDFs lesen?“ Ja, dazu mehr in Teil III.
  • Claude neu starten / Gespräch löschen: /exit, dann claude. Mit /clear beginnt man ein neues Gespräch im selben Fenster. Das alte bleibt erhalten und lässt sich mit /resume wieder öffnen. claude -c setzt das letzte Gespräch in diesem Ordner fort (Stand 2026-11, [KB] 25, §Sessions and context).
  • Enter schickt sofort ab, ich wollte eine neue Zeile: Neue Zeile mit Ctrl+J (geht überall). Shift+Enter geht im VS-Code-Terminal erst nach /terminal-setup einmalig in Claude (Stand 2026-11, [KB] 25, §Input).
  • Mehr Tasten und Tricks: Kurzer Verweis auf 1.9 Claude Code bedienen.

Material & Quellen

  • Doku Quickstart: https://code.claude.com/docs/en/quickstart

1.7 Berechtigungen

Dauer: ca. 10 Min.

Worum geht's

Im Manual-Modus fragt Claude, bevor es Dateien ändert oder Befehle ausführt. Lies, was es vorhat, bevor du zustimmst: Du bist die Chefin, Claude ist der Assistent. Das Fragen ist keine Störung, sondern deine Kontrolle. Seit v2.1.283 startet Claude Code im Auto-Modus (ein zweites Modell entscheidet statt dir). Wir haben in 1.4 auf Manual umgeschaltet, damit ihr die Abfragen seht. Auto kommt hier als „für später“.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • eine Berechtigungsabfrage lesen und verstehen, was Claude vorhat,
  • zwischen „Ja“, „Ja, und nicht mehr fragen“ und „Nein“ bewusst wählen,
  • ein „Nein“ nutzen, um Claude umzusteuern,
  • den aktuellen Modus in der Fußzeile erkennen und mit Shift+Tab wechseln,
  • erklären, warum sie nicht blind alles erlauben.

So erklären wir es

  1. Bild: Handwerker im Haus.

    Du lässt jemanden in deiner Wohnung arbeiten. Bei Kleinkram sagst du „mach einfach“. Wenn er die Wand durchbohren will, fragt er vorher. Genau so arbeitet Claude.

  2. Was Claude fragt (nur im Manual-Modus): Ohne Rückfrage liest es Dateien im Projektordner und führt eingebaute Nur-Lese-Befehle aus (ls, cat, grep, git status). Fragen tut es bei Dateiänderungen, anderen Shell-Befehlen und Web-Zugriffen (Stand 2026-11, [KB] 11, §1. Tool approval defaults). Im Auto-Modus gilt das nicht, siehe Punkt 6.
  3. Die Abfrage lesen, in drei Fragen: (1) Was? (Datei anlegen, Befehl ausführen) (2) Wo? (nur im Projektordner?) (3) Verstehe ich das? Wenn nein: „Nein“ und Claude fragen: „Erkläre mir, was dieser Befehl tut.“
  4. Die Optionen (so oder ähnlich im Terminal, der Wortlaut kann sich ändern; Stand 2026-11, [KB] 25, §Permission prompts):
    • Ja: einmal erlauben.
    • Ja, und nicht mehr fragen: für diese Art von Aktion merken. Für Befehle (auch Web-Domains und Websuche) gilt das dauerhaft für dieses Projekt: Es steht dann in .claude/settings.local.json. Für Dateiänderungen gilt es nur bis Sitzungsende. Manche Abfragen bieten nur „Ja“ (einmal). Zu Beginn sparsam nutzen.
    • Ja, und in den Auto-Modus wechseln: erlaubt und schaltet den Modus um. Gibt es nicht bei jeder Abfrage. Hier nicht wählen, wir bleiben in Manual.
    • Nein: ablehnen. Ein bloßes Esc bricht den ganzen Arbeitsschritt ab. Mit Tab auf „Nein“ kann man stattdessen eine Begründung mitgeben („mach es so …“). Claude macht dann mit dieser Begründung weiter. Das ist der Weg zum Umsteuern.
  5. Warum gut: Claude kann sich irren oder missverstehen. Die Abfrage ist die Stelle, an der wir Fehler abfangen, bevor sie passieren. Später kommt Git als zweite Sicherheit (2.1).
  6. Modi, nur erwähnen: Es gibt Stufen von „fragt bei allem“ bis „fragt fast nie“. Wechsel mit Shift+Tab, Reihenfolge ab Auto: Manual → Accept edits → Plan → Auto (Windows: ggf. Alt+M). Die Fußzeile zeigt den Modus: manual mode on, accept edits on, plan mode on, auto mode on (Stand 2026-11, [KB] 25, §Permission modes).
    • Manual: fragt bei allem außer Lesen. Hier lernen wir.
    • Auto: Ein Prüfmodell entscheidet statt dir. Harmloses läuft durch, du siehst nur eine Meldung, wenn etwas blockiert wird. Blockiert werden z. B. Programme aus dem Internet laden und sofort ausführen (curl | bash), Force-Push, git reset --hard und das Senden sensibler Daten nach außen. Für später, wenn du dich sicher fühlst und lange Aufgaben laufen lassen willst. Wer Auto nutzt, sollte vorher committen (2.4). [KB] 11, §3. Permission modes)
    • Accept edits: Dateiänderungen laufen ohne Frage. Achtung: Auch gängige Dateibefehle wie rm, mv, cp laufen im Projektordner ohne Frage, nicht nur Bearbeiten. Kann also auch löschen.
    • Plan: Claude liest und plant, ändert aber nichts, bis du den Plan freigibst. Kommt in 4.2.
    • Bypass permissions („Berechtigungen komplett überspringen“) nennen wir nur als Warnung: nicht für Anfänger, nur in Container oder VM.
  7. Wichtig: Die Regeln erzwingt das Programm, nicht Claude. Ein „Bitte frag nicht“ im Prompt ändert nichts (Doku).
  8. Prompt-Müdigkeit: Wer in einer Stunde 50 Abfragen bestätigt, liest sie bald nicht mehr. Das ist selbst ein Sicherheitsrisiko. Ziel sind weniger, aber wichtigere Abfragen. Genau dafür gibt es Auto und gezieltes „nicht mehr fragen“ ([KB] 11, §Core concept).

Zeigen (Live-Demo)

  1. Fußzeile prüfen (manual mode on). Claude eine Datei anlegen lassen, bei der Abfrage anhalten und laut vorlesen:
    Lege eine Datei checkliste.md an mit einer Packliste für eine Skitour.
  2. „Nein“-Demo: Bei einem zweiten Prompt ablehnen und umsteuern:
    Lösche alle Dateien in diesem Ordner, die mit "test" anfangen.
    Hier lesen wir den Befehl, zeigen auf das rm bzw. Löschen, wählen Nein und sagen: „Zeig mir erst, welche Dateien das wären.“ (Vorher harmlose Testdateien anlegen.)
  3. Kurz zeigen: Mit /permissions sieht man die Regeln und aus welcher Datei sie kommen. Im Auto-Modus listet es auch zuletzt blockierte Aktionen (Stand 2026-11, [KB] 11, §2. Permission rules).
  4. claude --permission-mode auto zeigen (Pflicht, 2 Min.): /exit, dann claude --permission-mode auto starten, Fußzeile zeigt auto mode on. Dazu --permission-mode manual und plan nennen. Das steht als Spickzettel auf der Schüler-Seite: Nach dem Kurs ist Auto der Normalfall, vorher committen (Stand 2026-11, Claude Code 2.1.332, Doku).
  5. Optional (1 Min.): Shift+Tab bis auto mode on durchschalten und denselben Löschen-Prompt zeigen. Er läuft ohne Abfrage. Danach zurück auf Manual. So sehen alle den Unterschied.

Selbst machen (Übung)

  1. Prompt: „Lege einen Ordner notizen an und darin eine Datei heute.md mit drei Stichpunkten.“
  2. Bei jeder Abfrage laut lesen: Was will Claude tun? Dann zustimmen.
  3. Zweiter Prompt: „Lege mit dem Terminal-Befehl mkdir einen Ordner archiv an.“ Hier den Befehl lesen und erklären, was er tut. (Nicht ls bzw. dir: Nur-Lese-Befehle fragen nie, da gäbe es nichts zu lesen. Es muss eine schreibende Aktion sein.) Reflexion: „Bei welcher Aktion würdest du nie ‚nicht mehr fragen‘ wählen?“ (Löschen, Befehle aus dem Internet, alles mit Passwörtern.)

Stolpersteine & Fragen

  • „Es nervt, dass es ständig fragt.“ Normal am Anfang. Erst Muster erkennen, dann gezielt „nicht mehr fragen“ für harmlose, wiederkehrende Dinge.
  • „Bei mir fragt nichts.“ Auto-Modus. Fußzeile prüfen, Shift+Tab bis manual mode on (1.4).
  • Versehentlich „nicht mehr fragen“ gewählt: Regeln mit /permissions ansehen und entfernen.
  • Blind „Ja, Ja, Ja“ drücken: Das größte Risiko. Wir üben bewusst das Lesen.
  • Befehle sind kryptisch: Normal. „Erkläre mir den Befehl in einem Satz, ohne Fachwörter.“
  • „Kann Claude außerhalb des Ordners etwas ändern?“ Standardmäßig nicht ohne Rückfrage. Details in der Doku, nicht vertiefen.
  • Alte Doku/Videos zeigen andere Texte: Wortlaut ändert sich, und ältere Versionen starteten im Manual-Modus. Wir halten uns an das Prinzip.
  • Datenschutz: Was Claude liest, geht an den Anbieter, siehe O.1.

1.9 Claude Code bedienen

Dauer: ca. 10 Min.

Worum geht's

Eine Handvoll Tasten reicht, um Claude Code sicher zu steuern: senden, neue Zeile, stoppen, zurückspulen, Modus wechseln. Fünf Tasten zuerst, der Rest kommt mit ?. Bisher war das über mehrere Themen verstreut. Hier steht es an einer Stelle, als Spickzettel.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • einen Prompt über mehrere Zeilen schreiben, ohne ihn aus Versehen abzuschicken,
  • Claude stoppen und mit einer Korrektur weiterarbeiten lassen,
  • am Fuß des Fensters ablesen, in welchem Modus Claude gerade arbeitet,
  • ein neues Gespräch beginnen und ein altes wieder aufnehmen.

So erklären wir es

  1. Bild: Fernbedienung.

    Du musst nicht jede Taste kennen. Play, Pause, Zurück und Lautstärke reichen fürs Fernsehen. Bei Claude sind es fünf.

  2. Die fünf Tasten (Empfehlung aus [KB] 25, Practical tips; Stand 2026-11):

    Taste Was passiert
    Esc Stoppt Claude. Was schon gemacht ist, bleibt. Dann Korrektur tippen.
    Esc Esc (Eingabe leer) Zurückspulen (/rewind): Gespräch und/oder Dateien auf einen früheren Stand.
    Shift+Tab Modus wechseln (Windows ggf. Alt+M). Der Modus steht unten im Fenster.
    Strg+O Zeigt ausführlich, was Claude gemacht hat (Werkzeuge, Befehle).
    ? Zeigt alle Tastenkürzel.

  3. Achtung Enter: Enter schickt sofort ab, auch einen halben Satz. Neue Zeile: Strg+J (geht überall) oder \ und dann Enter. Shift+Enter geht in Ghostty, Windows Terminal und Apple Terminal direkt, im VS-Code-Terminal erst nach /terminal-setup ([KB] 25, Input).

  4. Die drei Zeichen am Anfang einer Nachricht:

    • @ + Dateiname: „Schau dir genau diese Datei an.“ Zeigen statt beschreiben.
    • / öffnet das Befehlsmenü (z. B. /clear, /context, /usage).
    • ! führt einen Befehl selbst aus, ohne Rückfrage (z. B. ! git status). Claude sieht das Ergebnis und reagiert darauf.

  5. Der Modus unten im Fenster ([KB] 25, Permission modes; Stand 2026-11, Claude Code ab v2.1.283):

    • auto mode on: Claude startet so. Ein zweites Modell prüft im Hintergrund und erlaubt Harmloses selbst.
    • manual mode on: Claude fragt vor jeder Änderung. So arbeiten wir im Workshop (einmal Shift+Tab nach dem Start).
    • accept edits on, plan mode on: kommen in 1.7 und 4.2.

  6. Während Claude arbeitet, darfst du tippen. Mit Enter wird die Nachricht vorgemerkt und Claude liest sie, sobald der aktuelle Schritt fertig ist. So korrigierst du, ohne zu stoppen.

  7. Gespräche:

    • /clear: frisch anfangen, gleicher Ordner. Das alte Gespräch ist nicht weg.
    • /resume bzw. claude -r: ein altes Gespräch wieder aufnehmen. claude -c: das letzte fortsetzen.
    • Beenden: /exit oder zweimal Strg+C.

  8. Zurückspulen hat Grenzen: Esc Esc stellt nur Änderungen wieder her, die Claude mit seinen eigenen Datei-Werkzeugen gemacht hat, nicht solche durch Befehle. Das echte Sicherheitsnetz ist Git (2.6).

Zeigen (Live-Demo)

Im Ordner segeltoern aus 1.4:

  1. Unten auf den Modus zeigen, Shift+Tab drücken, bis manual mode on steht.
  2. Mehrzeiligen Prompt mit Strg+J schreiben:
    Lies @ideen.md.
Ergänze bei jeder Idee eine Zeile „Bester Monat“.
  3. Mittendrin Esc drücken, dann tippen: „Nur für die ersten zwei Ideen.“
  4. Esc Esc zeigen: das Menü öffnen, einen früheren Stand auswählen, „Never mind“ (nichts ändern).
  5. ? drücken und die Übersicht zeigen.

Selbst machen (Übung)

  1. Schalte auf manual mode on.
  2. Schreib einen Prompt über drei Zeilen (mit Strg+J), der eine Datei per @ nennt.
  3. Stoppe Claude einmal mit Esc und gib eine Korrektur.
  4. Öffne mit Esc Esc das Zurückspulen-Menü und schließe es wieder.

Geklappt, wenn du alle vier Schritte ohne Spickzettel schaffst.

Stolpersteine & Fragen

  • „Mein halber Prompt ist weg!“ Enter statt Strg+J gedrückt. Mit Esc stoppen, dann weiterschreiben.
  • Esc Esc löscht meinen Text: Steht schon Text in der Eingabe, leert Esc Esc ihn (mit Pfeil-hoch zurückholen). Das Menü kommt nur bei leerer Eingabe.
  • Shift+Tab tut nichts (Windows): Alt+M probieren.
  • Kein Modus zu sehen / Claude startet in manual: Organisationen können den Auto-Modus abschalten. Dann ist alles gut so.
  • Tastennamen: Auf dem Mac ist Strg die control-Taste, nicht cmd.

O.5 Modell, Effort und Abo-Limits

Dauer: ca. 10 Min.

Worum geht's

Ein Pro-Abo ist nicht unbegrenzt. Wer lange Sitzungen, große PDFs und mehrere Agenten nutzt, stößt mittags ans Limit. Drei Regler bestimmen den Verbrauch: Modell, Effort, Länge des Gesprächs. Wer sie kennt, kommt durch den Tag.

Ablaufdatum: Modelle, Preise und Limits ändern sich alle paar Monate. Alles hier: Stand 2026-11 ([KB] 16, zuletzt geprüft 2026-11-10). Vor dem Workshop neu prüfen.

Lernziel

Nach diesem Thema können die Teilnehmenden …

  • mit /usage nachsehen, wie viel vom Limit verbraucht ist,
  • mit /model das Modell wählen,
  • erklären, warum ein langes Gespräch mehr kostet als ein kurzes,
  • Effort anpassen statt gleich das Modell zu wechseln,
  • sagen, was man auf Pro besser nicht einschaltet.

So erklären wir es

  1. Bild: Handyvertrag mit Datenvolumen.

    Pro ist wie ein Tarif mit Datenvolumen. Es gibt ein Kontingent für 5 Stunden und eines für die Woche. Chat im Browser und Claude Code teilen sich dasselbe Volumen.

  2. Die drei Regler ([KB] 16, Three knobs):
    • Modell (/model): wie stark und wie teuer. Auf Pro ist Opus 5.5 voreingestellt. Sonnet 5.5 ist günstiger und reicht für Alltägliches. Haiku empfehlen wir für Agenten-Arbeit nicht. In der Claude-App: Auswahl unten im Eingabefeld.
    • Effort (/effort): wie gründlich Claude nachdenkt und prüft. Stufen low, medium (Standard), high, xhigh, max.
    • Gesprächslänge: Claude hat kein Gedächtnis. Bei jeder Runde wird das ganze Gespräch neu geschickt (3.6). Lange Gespräche verbrauchen also mit jeder Runde mehr.
  3. Erst Effort, dann Modell. Effort ist der feinere Regler. Ein Modellwechsel mitten im Gespräch ist teuer: Das neue Modell muss alles von vorn lesen ([KB] 16, Two more rules).
  4. Billig ist nicht immer günstig. Ein schwaches Modell, das scheitert, kostet einen zweiten Versuch und deine Zeit ([KB] 16, Cost per solved task).
  5. Nach der Mittagspause neu anfangen. Auf dem Abo merkt sich Claude das Gespräch etwa eine Stunde lang günstig (Cache). Danach wird alles wieder voll berechnet. Nach einer langen Pause: /clear und mit einer kurzen Zusammenfassung starten ([KB] 16, Subscription vs. API; [KB] 17).
  6. Was auf Pro Extra-Geld kostet: Das Modell Fable und der Schnellmodus /fast laufen auf Pro nur über bezahlte Zusatz-Credits ([KB] 16, Plans; Fast mode). Nicht aus Versehen einschalten.
  7. Mehrere Agenten sind teuer. Laut Anthropic braucht ein Agent etwa 4-mal so viele Tokens wie ein Chat, ein System mit mehreren Agenten etwa 15-mal so viele ([KB] 07/13). Hilfs-Agenten laufen standardmäßig mit demselben Modell wie das Hauptgespräch (5.5).
  8. Für eine einzelne harte Frage: ultrathink in den Prompt schreiben. Das erhöht die Gründlichkeit nur für diese eine Antwort.

Zeigen (Live-Demo)

  1. /usage aufrufen: die Balken für 5 Stunden und Woche zeigen. Auf Vorschläge hinweisen (z. B. „Switch … effort“). In der Claude-App steht dasselbe unter Einstellungen → Nutzung.
  2. /model zeigen: Liste der Modelle, Opus ist ausgewählt. Nichts umstellen.
  3. /context aufrufen: wie voll das Gespräch ist.
  4. /effort zeigen: Schieberegler, Standard medium.
  5. Gleiche Frage einmal mit low, einmal mit high stellen, z. B.:
    Wie viele Höhenmeter mache ich auf einer Skitour von 1.200 m auf 2.650 m, wenn ich zwischendurch 150 m abfahre und wieder aufsteige?
    Wir vergleichen Dauer und Antwort.

Selbst machen (Übung)

  1. Ruf /usage auf und notiere, wie viel vom 5-Stunden-Fenster schon verbraucht ist.
  2. Stell dein Effort auf low und lass dir drei Ideen für dein Projekt geben. Dann zurück auf medium.

Geklappt, wenn du sagen kannst, wo du dein Limit siehst und welchen Regler du zuerst drehst.

Stolpersteine & Fragen

  • „You've hit your limit“: Warten, bis das Fenster zurückgesetzt wird. Ein Modellwechsel hilft nur, wenn die Meldung ein bestimmtes Modell nennt („Opus limit“) ([KB] 16).
  • „Welches Modell ist das beste?“ Für den Workshop: beim voreingestellten Opus bleiben, Effort medium.
  • Wie viel ein Modell vom Limit frisst, veröffentlicht Anthropic nicht genau. Faustregel: größeres Modell, höherer Effort, längeres Gespräch = schneller am Limit.
  • Deutsch braucht mehr Tokens als Englisch (grob 1,5–1,8 statt 1,2 pro Wort; gemessen bei OpenAI-Tokenizern, für Claude nicht belegt, [KB] 26).
